### A.1.STM:9 - Common anti-patterns

| Anti-pattern | Repair |
| --- | --- |
| Mantra as fixed work sequence | Use its connected questions to construct and criticize hypotheses; use direct patterns for local truth and WorkPlan for planned order. |
| Correct parts, unsupported whole | Recover the conditions under which the particular answers can be used together; revise the failed connection or candidate rather than counting completed questions. |
| Short formula replaces knowledge | Return to the developed subject explanation and bring its premises and limits into the common account. |
| A new contract hides an unchanged purpose | For the same organizational work, retain the product use, creator capability and finite local acceptance under section 4.1.1. A genuine new product supply needs its own usable result, recipients and fitness obligations; a new budget or contractor does not provide them. |
| Role becomes an intrinsic system type | Separate the SoI role from its holder and description; test the actual System under A.1 and any technical role claim under A.2/A.2.1. |
| Project equals network | Keep actual project as composite `U.Work` and E.18.NET as a selected non-agentive `U.Structure`. |
| Case equals subnetwork | Keep the local question and its receiving use clear. Recover the closure basis when closure is at issue; select a structure only when one receiving use needs the whole organization. |
| Creator graph import | Explain the required creator contributions and their relations. When a TFS network is claimed, identify its members and obtaining cross-member occurrences; an arrow adds no creator kind or generic `creates` relation. |
| Shared entity as edge | Name the directly governed production, inception, participation, use, feedback, or other occurrence and bind its participants. |
| Architecture or provision chosen before its use basis | Recover receiving changes and encompassing functioning at the operating time, then justify inward and creation-side choices. |
| Maker treated as suprasystem | Recover the creation or provision relation; use a containing-system claim only where the product is actually or prospectively a proper part at the stated time. |
| Intended system acts | Keep it in plan or description content until identity inception; only an existing admitted system can perform Work. |
| Systemhood proves Work | Test causal participation, system-role assignment, Method, Work, and transformation separately. |
